# README와 PR 템플릿 보강

사용자 요청: 저장 방식 같은 기술 소개 대신 게임의 재미가 보이는 소개, 다른 레포를 웹 리서치한 화려한 README, 팀 PR 스킬과 비교한 템플릿 장점 반영. 영어판 요청은 철회되어 한국어만 작성한다.

## 참고한 공개 문서와 선택

- [PokeTokenBar 개인 포크](https://github.com/semi0x3b/PokeTokenBar): 로고·짧은 소개·바로 쓰는 경로, 실제 화면/GIF와 기능 설명을 짝지은 투어. 문구와 기능은 복사하지 않는다.
- [PokéRogue](https://github.com/pagefaultgames/pokerogue): 플레이 경로와 기여/자료 조건을 구분하는 구조.
- [Mindustry](https://github.com/Anuken/Mindustry): 시각 자료와 실행/기여 경로의 우선순위.
- 기존 팀 PR 작성 스킬: 대상 브랜치 기준의 커밋된 diff, 사용자의 문제/행동으로 설명, 체크리스트의 실제 근거, 저장/설정/외부 의존성/반영 순서, 최종 범위에 맞춘 본문 갱신. 회사 전용 명칭·절차·파일 경로는 공개 문서로 옮기지 않는다.

README는 로고 → 실제 걷기 GIF → 게임 투어 → 학습/시작 안내 순으로 구성한다. 부모 잠금·저장·개발 절차는 접어 두고, 자료 권리는 하단에 유지한다. 새 게임 기능이나 영어 번역은 추가하지 않는다. 외부 통계·별점·추적 배지는 넣지 않고 게임의 기존 그림과 새 실제 화면을 쓴다.

사진은 localhost의 별도 시험 수첩에 소개용 기록을 넣고 실제 UI로 촬영한다. 모험/수집 기록이 실제 아동의 자료나 정식 플레이 성과인 것처럼 표시하지 않는다. 원본·시험 스크립트·결과는 .test/readme-showcase/, 문서용 압축 이미지는 docs/showcase/. GIF는 실제 연속 캡처로 만든다.

PR 템플릿은 전후 이미지를 앞에 유지하며 근거 있는 검증 표·저장/설정/외부 의존성 영향·반영 순서를 추가한다. 기술 체크를 모든 PR에서 장문으로 요구하는 안은 버리고, 영향 없음/문서 변경은 이유 한 줄로 쓰게 한다. 템플릿을 없애고 개인 스킬만 쓰는 안은 사용자가 GitHub 자동 템플릿을 원해 채택하지 않는다.

README/기여 문서만 바뀌므로 앱 버전 변경·운영 재배포는 필요 없다. GitHub 기본 브랜치에서 문서와 자동 PR 템플릿이 보이는지 확인한다. 남아 있는 원작 권리·이전 서버 기록·실기기 검증 범위는 확대해 완료로 보고하지 않는다.
